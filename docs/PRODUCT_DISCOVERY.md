# WELOS — Product discovery

Audit of `tejaswi-raghav/welos-app` at `1c43414` (main), read from source rather than from the name. Everything below is traceable to a file in this repository; anything that is not is listed under *Assumptions*.

## The answer in one line

**WELOS is a rooftop unit for UAE homes and buildings that makes electricity from sun (and wind, where it pays) and collects rain, with an on-board controller that decides, every cycle, where each watt and litre goes.**

That is the sentence a first-time visitor needs in the first five seconds. The old site led with "SUN. WIND. WATER." which names inputs but not the product, the user or the outcome.

## The ten questions

| # | Question | Answer from the code | Source |
|---|---|---|---|
| 1 | Real-world problem | A UAE roof is idle area under intense sun. Homes buy all their electricity (AC-heavy load) and water from the utility, dust silently cuts solar output, and the rare heavy storms run straight down the drain. ## Numbers that disagreed (resolved)

The old site quoted three different systems as if they were one:

| Context | Solar | Battery | Wind | Tank |
|---|---|---|---|---|
| Exploded-view panels ("System 01 prototype") | 800 W | 3.5 kWh | 400 W | 300 L |
| Control simulator (`simulator.js` + `DEFAULT_CONFIG`) | 3.6 kWp | 24 kWh | ~1.2 kW cap | 420 L |
| Sizing engine, Dubai villa, Recommended | 10.5 kWp | 20 kWh | not recommended | 300 L |

**Resolution:** the redesign uses a single, named **reference build** on the marketing site: *WELOS S · Villa · Recommended · Dubai preset climate*, computed live by `sizeSystem()` so it can never drift from the engine. Hero readouts and the day simulation run the real control engine with its battery capacity and charge limits set from that build. The 3D model is labelled as the system *architecture*, not a to-scale model of every build. The prototype figures (800 W etc.) were removed from the story because nothing else in the product uses them. Control OS keeps its own simulator configuration and now says so in its header.

## Data integrity rules adopted

- Every number on the site is one of: **engine output** (sizing or control engine, deterministic), **engine assumption** (a constant in `RATES` or `DEFAULT_CONFIG`), **simulated** (inputs generated in the browser), or **target** (concept specification). Each is labelled where shown.
- No measured, "live" or validated data exists, so nothing is labelled as such. Control OS "Link healthy" was a fake connection indicator and is now "Simulator · not connected to hardware".
- No savings percentages, testimonials, customer logos or benchmarks were added.

## Assumptions (unresolved, documented rather than invented)

1. **Hourly profiles.** The engines work on daily climate means (sizing) and instantaneous sensor values (control). The new "one day on your roof" chart needs an hourly shape. It uses a half-sine irradiance curve scaled to the climate's daily kWh/m², and an *illustrative* AC-led villa load shape scaled to the daily load input. Both are labelled as illustrative; the routing decisions on top of them come from the real control engine.
2. **Hero conditions.** The five hero scenarios are hand-set sensor snapshots (noon, evening, dust, storm, outage) for the reference build with the optional 1 kW wind module fitted, so the turbine can be shown working. The routing and mode shown are computed by `evaluateController()`.
3. **PV conversion in simulations** follows `simulator.js` (irradiance × kWp × efficiency, soiling and heat derate) so the hero, the day chart and Control OS speak the same physics.
4. **Audience.** The UAE villa owner is treated as primary because tier S is the default everywhere and the copy is UAE-specific; investors are a secondary audience served by the "What's real today" section.
